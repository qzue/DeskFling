## 已测 CPU 数值

以下为 **每个活动 tick 的物理 CPU 耗时（毫秒）**，不含输入、规则、绘制或显示。休眠/暂停 tick 不做物理，故 samples 可以小于 36,000。取排序样本中 floor(p×(n−1)) 的值。

| 对象 | 场景 | 物理样本 | 中位数 ms | P95 ms | P99 ms |
|---|---|---|---|---|---|
| 50 | fall | 7440 | 0.0135 | 0.021375 | 0.032125 |
| 50 | stack | 7440 | 0.012334 | 0.016 | 0.0185 |
| 50 | switch | 23550 | 0.013625 | 0.017625 | 0.023 |
| 200 | fall | 7920 | 0.050375 | 0.062083 | 0.073625 |
| 200 | stack | 18840 | 0.110875 | 0.127084 | 0.150708 |
| 200 | switch | 36000 | 0.095292 | 0.113916 | 0.1555 |
| 500 | fall | 7980 | 0.127583 | 0.17325 | 0.299 |
| 500 | stack | 17220 | 0.331167 | 0.384791 | 0.441834 |
| 500 | switch | 36000 | 0.207292 | 0.302209 | 0.345792 |

全部 18 组合的输入/物理/规则/绘制中位数、P95、P99、样本数和整段 elapsed 在 原始记录。`samples=0` 的阶段没有测量值，输出的 0 是空样本标记，不代表零成本测量。

- fall：每 600 tick 重建散落场景，覆盖自由落体/堆叠/休眠。
- stack：压缩横向间距，制造密集接触，周期性重建。
- throw：固定周期抓取/拉动/抛掷第一个对象，其余物体可休眠；这是输入压力路径，不代表所有物体持续活跃。
- sleep：先预热直到全部休眠，然后测调用路径；物理样本数为 0，证明没有继续步进，不等于已测原生进程空闲 CPU%。
- pause：每 120 tick 切换暂停，恢复后最终休眠；测暂停路径不积压历史时间。
- switch：每 120 tick 切换重力/台球，台球多一个白球；总体 elapsed 包含重建，分阶段 physics 不包含重建开销。

## 第二轮原生测量与实际优化

代码：`platforms/macos/native_measurement.h`、`diagnostics.h`、`sandbox.mm`。使用 Release AppKit/Core Animation 真窗口、50 个合成对象，工作区 **1100×700 points / 2× backing**，不是 1920×1080 等效验收。macOS 15.7.5 / M1 Pro / 32 GiB；配置与屏幕逐份存入 JSON。

每次预定时长的 80% 为每 2 秒重置一次的重力场景，5% 留作沉降，7.5% 静止，7.5% 暂停；1 Hz 记录进程累计 CPU、resident 内存、图像/图层池、刚体/awake、前台/可见状态。百分位取有界环中排序后 floor(p×(n−1))，每阶段最多 36,000 个样本；空样本为 null。物理指标是每 tick 内实际步进累计 CPU 时间，不是每个 Box2D 子步时间。

CPU submission 计时覆盖本进程图层属性/图像/路径更新与 CATransaction commit，不等待 GPU，标题等提交计时区外工作由进程 CPU 统计涵盖。进程 CPU 使用 getrusage 用户+系统时间 / wall time，100%=一个逻辑 CPU；包含测量开销，不含 WindowServer、GPU 或整机功耗。resident 不是全部渲染资源的 GPU 内存。

### 有证据的缓存改动

同机同一 20 秒脚本，原实现每帧 `contents=nil` 再指定 NSImage。改为仅初始化时解码 6 张 CGImage，图层只在纹理身份改变时重新绑定，切换非 sprite 时才清除。未换渲染后端或物理引擎。

| 20 秒脚本的活动阶段 | CPU 提交 median ms | P95 ms | P99 ms | 进程平均 CPU |
|---|---:|---:|---:|---:|
| 改动前 | 4.782 | 6.869 | 7.377 | 21.206% |
| 缓存后 | 0.613 | 1.163 | 1.376 | 5.019% |

证据：改动前、缓存后。均 completed=true / exit 0。短测试只支持本机此合成负载下 CPU 提交成本下降，不能推导稳定帧率或跨机器提升比例；不是隔离负载、多轮置信区间实验。

600 个内存采样：首/末/最小/峰值 **68.312 / 62.562 / 60.312 / 68.969 MiB**。图像始终 6，图层池由 50 达到 51 后复用，刚体始终 50；本次采样未见持续增长，但不是泄漏证明。静止阶段物理/绘制/提交无样本；暂停转换仅有 1 次提交。应用由 5 Hz 空闲 timer 驱动，不重复物理步进和提交。运行期间早期存在一次探针编译及正常其他应用活动，未控制整机负载，不把这些单次结果作为硬件上限。

旧报告的回调 interval median/P95/P99 = **18.060 / 18.833 / 200.311 ms**，大于 33.34 ms 计数 232。分析源码发现每 2 秒重置可能在 5 Hz 休眠等待后发生，旧代码按当前 active 状态把等待算入活动间隔；因此 **232 不能当成渲染卡顿数，200 ms 不是呈现 P99**。现在 `Playground::tick` 只统计两端都活动的回调，排除初始化、重置、恢复、休眠唤醒的第一个间隔；新增专项单测通过。重置等操作成本仍在整个进程 CPU 统计中，不属于纯物理步进统计。

### 最终二进制补测与中断

第二次请求 600 秒的 补测报告 在 **73.093 s** 经正常退出路径结束（exit 0，但 completed=false）。样本内发生 50→51 刚体/台球模式切换，不能视为标准重力工作负载或完整长跑通过，也不拿它与缓存前后结果直接比较。退出原因未被当时版本细分记录，不能据此归因于用户或系统。

因此最终记录器新增 `mode`、`user_interactions`、`focus_lost`、`workload_valid`。人工改变玩法后不再自动重置/暂停抢回控制；duration 完成与工作负载有效性分开。未来验收须同时检查 completed、workload_valid、前台/可见数量、实际刚体与 awake，不能只看退出码或请求时长。

最终版本另执行 20 秒短测：20.003 s、completed=true、workload_valid=true、user_interactions=0、focus_lost=false；四阶段均走完。活动回调 median/P95/P99 为 **18.167 / 18.852 / 20.046 ms**（737 样本），不再出现脚本重置带来的约 200 ms 尾值。该短测同时有 Debug/ASan 编译与测试活动，只用作最终计时/有效性标记的功能验证，不能替代最终版本十分钟或独立性能基准。

## 原生面板与仍未测量的范围

P 面板是现场调试用 rolling samples，不代表独立显示 profiler。最终命令行报告提供 input/physics/rules/draw/submit/interval 的 median/P95/P99、长回调计数及资源/内存趋势。`NSTimer` / `WM_TIMER` 的回调不是显示呈现帧；**GPU 完成时间、真实呈现 FPS、整机功耗仍为不可用**。不能使用 1/physics 或 1/callback interval 宣称产品 FPS。第一轮没有原生 CPU/长跑记录，本轮已补上述有边界的证据。

最终统计口径下十分钟、1080p 等效、真实呈现 60 FPS、Windows 和真实桌面负载仍未验收。没有使用 Metal、复杂多线程、自定义分配器或 fast-math。原始证据与明确的未通过项均保留。
